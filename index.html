Your experience stays yours.

Smaller projects and supporting research

These focused experiments explore parts of the wider direction. They are at different stages and are not presented as one integrated product.

Rosetta · bounded translation experiments

Why it exists: explore one checked representation linking structured intent, Rust output, and selected machine-code forms.

Where it stands: a bounded Rust translation toolkit supports selected x86-64 and AArch64 instructions. Its documented CI covers listed test vectors; full machine-code semantic equivalence and a general compiler are not claimed.

Useful help: independent ABI and instruction review, plus evidence-backed tests before adding supported forms.

Synapse · agent coordination

Why it exists: explore how specialized agents and tools can coordinate around scoped work.

Where it stands: Project documentation describes a Rust agent host with a terminal interface, Hive-backed state, model routing, and approval-gated tools. The current source labels itself a 1.0.0 release candidate; Android build and device acceptance, provider and OAuth validation, and other production release gates remain open.

Useful help: Android ARM64 build and device acceptance, provider/OAuth and MCP integration review, and release validation.

MemoryCore · curated project memory

Why it exists: keep selected project facts available across work sessions without requiring a hosted model or internet connection for storage and recall.

Where it stands: a local Rust storage and retrieval component; retrieval is not a pretrained semantic model.

Useful help: portability, retrieval-quality evaluation, and storage reliability review.

Nautilus · early model and learning experiments

Why it exists: investigate how constrained system ideas might inform small model and learning experiments.

Where it stands: recovered notebook and initialized runtime artifacts; no trained model, complete source dataset, or completed experiment is verified.

Useful help: reproduce the baseline, establish a licensed dataset, and report measurable results before making performance claims.

01 · Framework research

Universal Constraint Computing

In plain terms

Think of a clear instruction paired with guardrails: what the system is being asked to do, what actions are allowed, and what must stay off-limits.

Technical view

UCC research describes intent, context, possible effects, uncertainty, authority, and resource limits so a proposed action can be checked before execution. Complete end-to-end enforcement is not yet established.

02 · Operating-system research

SenseOS

In plain terms

An operating system is the foundation underneath apps. It starts the machine, decides how programs run, organizes files, and connects software to hardware. SenseOS is an experimental effort to build that foundation—not just another app.

Technical view

Current prototypes have tested pieces of boot handoff, persistent storage, program admission, filesystem access, capability checks, and interface input. These are partial paths; SenseOS is not a complete or production-ready general-purpose operating system.

03 · Interface research

SenseUI

In plain terms

SenseUI is the part people see and operate: a single, adaptable workspace for programs, information, and media instead of a pile of unrelated screens.

Technical view

Rust-based interface libraries and runtime foundations are in development. The intended design can arrange content from different system components, but a complete live desktop compositor and protected system boundary have not yet been demonstrated.

I began BlackBlaze in 2011 as a graphic design group, creating websites and corporate identities.
